# Findings of the alpha.2 rerun (class, evidence, root cause where found; nothing fixed, no issue or PR opened)

Classes: app bug, host bug, Tools bug, runner bug, environment. Status against alpha.1: FIXED / STILL FAILING / NEW.

## Host bugs
* **FJ-1b (Fiji host bug, STILL FAILING, was FJ-1; severe in practice).** Cancel on the tool CHOOSER is fixed, but Cancel on a tool FORM that has a required input left empty still runs the tool: `ui_fiji_panel_form_cancel FAIL: the summary does not say cancelled; a run started (status 'FAILED'); 1 run record(s) were created`; the record says `[missing_parameter] 'Output folder' is required` (results/alpha2/GuessTheCondition/ui_fiji, script mode and jar mode, real Robot click on Cancel, released alpha.2). Root cause (read in the released LabConstrictor_Tools.groovy, `harvest()` line ~737): `boolean pressed = harvested.canceled && info.inputs().findAll { it.isRequired() }.every { harvested.getInput(it.getName()) != null }`. The extra clause was added to tell a real Cancel from SciJava cancelling by itself when a required input cannot be filled (no image open), but a person who opens a form (the folder is required and empty) and presses Cancel is exactly that situation, so it is treated as "no press" and the run goes on. Passes only when all required inputs are filled, which is why the harness cases (`cancel_on_a_tool_form_runs_nothing_and_records_nothing`, PASS in real Fiji) and apps such as VLab4Mic (form_cancel PASS) do not show it. A distinguishing signal other than "required input empty" is needed (e.g. whether the dialog was shown).
* **H-N4 (Napari host bug, NEW status: now reproduced by hand on a real app, was "not claimed").** Stale callbacks of replaced forms: `controller.changed.connect(lambda *_: self._refresh_enabled())` (_widget.py line 641) stays connected to the widgets of every earlier form; when such a widget changes, `_refresh_enabled` runs against the CURRENT tool and form and raises `AttributeError: 'FunctionGui' object has no attribute 'pixel_size'` / `'region'` (psygnal EmitLoopError printed in the console; no dialog). Reproduction without the audit: results/alpha2/Playground/h_n4_repro.txt (open Playground 0.0.5, choose each of the 17 tools twice and flip the radio buttons of each form: 2 errors, `no attribute 'region'`). Seen in the audit as `ui_napari_form_bright_area_opens`, `ui_napari_run_bright_area`, `ui_napari_panel_tool_chooser` FAIL (Playground). Effect for a user: console errors and a refresh of the wrong form's enabled state is skipped; not shown to change a run's inputs.
* **N-1 (Napari host, NEW, probable): leftover top-level QRadioButtons.** Two audit steps of Playground (`ui_napari_run_look_inside_file`, `ui_napari_form_summarise_table_controls`) found 22 stray `QRadioButton` top-level windows next to the main window after many form changes ("top-level windows are [QRadioButton x22, _QtMainWindow]"). Probably the radio buttons of replaced forms, orphaned when their form is deleted. In the by-hand run of H-N4 only the main window was visible, so it needs the longer audit sequence. Not isolated further.
* **N-2 (Napari host behaviour, NEW, design question): a typed pixel size of 0 is silently replaced by the image's calibration.** In `_link_calibration.edited`, `link.state == UNSET` (cleared OR typed 0) refreshes from the image, so `bright_area` / `compare_images` with pixel size 0 cannot reach the tool's `invalid_pixel_size` refusal: the run uses the image's calibration (VLab4Mic `vm_pixel_zero`: COMPLETE with 0.02; Playground `pg_pixel_zero`: runs and ends `pixel_size_unknown` for an uncalibrated image instead of `invalid_pixel_size`). A person who types 0 is not told it is not a size. Napari form also refuses negative sizes itself with its own sentence (`'Pixel size' must be greater ...`), different from the tool's code; both are refusals.
* **VL-7 (Napari host, STILL FAILING): micrometre calibration written by Fiji is not recognised.** `vm_cal_micro` host-only dataset: box stays empty, expected 0.02 (`host showed reference_pixel_size_um = None`), with the file chosen in the 'or file' row. um, nm, none behave as truth. Cause as in alpha.1 (ImageJ writes `unit=µm`, the escape is not decoded before the unit lookup).

## Environment
* **E-1 Playground 0.0.5 installer fails on a 6 GB machine (exit 1, 5 min 40 s).** `post_install.sh` runs `pip install -r requirements.txt`; on Linux that pulls torch 2.8.0 with the whole CUDA stack from PyPI (about 4 GB download and 4 GB installed, plus the pip cache) even on a machine without a GPU. Here the disk filled up (`OSError: [Errno 28] No space left on device` while downloading nvidia_cudnn; results/alpha2/Playground/pip_requirements_ENOSPC.log) and the installer ended `ERROR: Application requirements installation failed`, leaving a half-installed prefix with no registration. To test the app I completed the install by hand: removed the CUDA wheels, installed torch 2.8.0+cpu, ran the release's post_install.sh again (everything after pip then ran: registration with hosts notebook, napari, fiji, qupath, launcher self-test). So the tested environment differs from a normal install only in torch's build; the sandbox row `1_installer_succeeds` is FAIL for this reason. Worth a note to users with small disks or no GPU (CPU wheel index), not a defect of the tested code.
* Other: the Python of the Fiji audit must be one with labconstrictor_tools (else the CLI replay of inexpressible prerequisites says "No module named labconstrictor_tools"): started it with the Napari venv.
